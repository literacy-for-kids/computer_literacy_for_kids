# Worked Examples and Optional Depth

Use these cards after the corresponding core teaching. They supply the scenario and a sample response; no external research, new account, real-world contact, or private disclosure is required. The examples are fictional teaching cases, not real measurements, medical guidance, legal rulings, financial advice, or promises of outcomes.

## Two kinds of optional work

- **Supplied practice:** the scenario, sample response, and depth question are on this page. Allow about 15–20 minutes for one card, with paper or oral explanation. Read the card before the session; a calculator is optional for arithmetic.
- **Open research prompt:** a request to locate or construct missing teaching material, such as outside sources, interview records, or a real-case packet. This is not supplied instruction. A tool activity with complete steps is still supplied instruction, even when an adult must prepare the device or account. An adult must select and verify materials, arrange access, and plan additional time first. Use the supplied card instead when those materials are unavailable.

Choose depth by readiness and interest, not age alone. Learners aged 10–12 can use the core teaching without taking every technical add-on; older-learner work remains optional. The depth questions are not prerequisites for the next core week or criteria for its checkpoint.

## How to use a card

1. Read the scenario and ask for a reasoned answer.
2. Let the learner draw, speak, sort, or write using the fictional case.
3. Compare with the sample: notice the evidence and the limits, not matching wording.
4. If ready, change the stated assumption using the depth question.
5. If the core idea is unclear, return to the linked lesson before adding complexity. A private or paper artifact is enough.

Sample responses illustrate reasoning, not scripts to memorize or the only defensible answer to an open choice. They do not require a learner to experience or disclose the situation.

## Week 1
**Core lesson:** [Week 1: Internet Playground](./week01-week-1-internet-playground.md)

**Supplied scenario and question:** A pretend search result says "Free game: give your password to start." What should Lee do?

**Illustrative response:** Lee should stop and ask a trusted adult. A search result is an invitation to investigate, not permission to share a password.

**Optional depth:** Compare it with a result that asks no personal information. Does that alone prove the second site is trustworthy? Explain why further checks still matter.

**Facilitator check:** Ask which stated fact or assumption supports the explanation. If that link is missing, model it with the sample and invite a second explanation. Assess reasoning and limits, not speed, exact wording, or personal experience.

## Week 2
**Core lesson:** [Week 2: The Computer Control Room](./week02-week-2-computer-control-room.md)

**Supplied scenario and question:** A learner types a letter, then clicks a button that opens a window. Identify two inputs and outputs.

**Illustrative response:** Typing and clicking are inputs. The displayed letter and opened window are outputs; the operating system helps the app and device respond.

**Optional depth:** Draw the route from keyboard to app to display. Name one reason an input might not give the expected output, such as the wrong window having focus.

**Facilitator check:** Ask which stated fact or assumption supports the explanation. If that link is missing, model it with the sample and invite a second explanation. Assess reasoning and limits, not speed, exact wording, or personal experience.

## Week 3
**Core lesson:** [Week 3: The Digital Treasure Chest](./week03-week-3-digital-treasure-chest.md)

**Supplied scenario and question:** Lee wants comments on a dummy story, then needs to restore yesterday’s saved copy. Choose access and recovery steps.

**Illustrative response:** Comment access permits feedback without editing. Copy the checked backup to a new restored filename, open it, and verify the text. Changes after the backup may be missing.

**Optional depth:** Explain why a same-device copy helps this rehearsal but cannot protect against losing the device. Never test by deleting real work.

## Week 9
**Core lesson:** [Week 9: Teach the Computer to Follow Instructions](./week09-week-9-teach-the-computer.md)

**Supplied scenario and question:** A paper robot must draw a square. "Draw something square-ish" is too vague. Improve the instructions.

**Illustrative response:** Repeat four times: draw a side of the chosen length, then turn 90 degrees. The order and repeat count make the intended shape testable.

**Optional depth:** Trace what happens with only three repetitions. Explain the difference between an unclear instruction and a clear instruction for the wrong result.

**Facilitator check:** Ask which stated fact or assumption supports the explanation. If that link is missing, model it with the sample and invite a second explanation. Assess reasoning and limits, not speed, exact wording, or personal experience.

## Week 11
**Core lesson:** [Week 11: The Debugging Lab](./week11-week-11-the-debugging-lab.md)

**Supplied scenario and question:** A variable starts at 0 and adds 1 three times. A second run has no reset. What values result?

**Illustrative response:** The first run ends at 3. The next ends at 6 if it keeps the old state. Resetting to 0 makes each run end at 3.

**Optional depth:** Replace add-one with set-to-one: the final value becomes 1. Explain why setting and changing are different operations.

**Facilitator check:** Ask which stated fact or assumption supports the explanation. If that link is missing, model it with the sample and invite a second explanation. Assess reasoning and limits, not speed, exact wording, or personal experience.

## Week 12

**Supplied scenario and question:** A bicycle has pedals, a chain, wheels, and brakes. How do two parts depend on each other?

**Illustrative response:** Pedals drive the chain, which drives a wheel. A broken chain can stop this path even when the wheel itself works; brakes have a different role.

**Optional depth:** Draw a component boundary and name an interface. Do not take apart equipment to complete the paper task.

**Facilitator check:** Ask which stated fact or assumption supports the explanation. If that link is missing, model it with the sample and invite a second explanation. Assess reasoning and limits, not speed, exact wording, or personal experience.
